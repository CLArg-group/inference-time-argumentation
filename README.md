# Neurosymbolic Learning for Inference-Time Argumentation

This repository contains the code and data for **inference-time argumentation (ITA)**, a trainable neurosymbolic framework for ternary (True / False / Uncertain) claim verification.

In ITA, an LLM generates arguments that support and attack a claim, and a base score model (BSM) assigns each argument a base score. A gradual argumentation semantics (DF-QuAD) then computes the strength of the claim, and fixed thresholds turn that strength into a verdict. The same semantics is used during training, so the argument generator (trained with GRPO) and the BSM are both optimised for the quality of the resulting argumentative predictions. At inference time, every verdict is computed from the generated arguments and their scores.

Our optimised model checkpoints are available in the [Inference-Time Argumentation collection](https://huggingface.co/collections/CLArg-group/inference-time-argumentation) on Hugging Face.

## Repository layout

```
configs/grpo/             GRPO training configs, one per trained argument generator
Data/                     Training, validation and evaluation data (see Data)
scripts/
  run_grpo_tuning/        GRPO training launcher (finetune_grpo.sh)
  run_evaluation/         Evaluation of trained argument generators (evaluate_grpo_run.sh)
  analyse_bootstrap.py    Bootstrap confidence intervals from prediction CSVs
  Ranked Arguments Generation.ipynb   Generation of the ranking dataset
src/ita/
  base_score_model/       BSM: priming, training, validation and inference
  grpo_finetuning/        GRPO training of the argument generator
  evaluation/             Argument generation and argumentative evaluation
  baselines/              Direct and argumentative baselines
  semantics/              Gradual semantics (DF-QuAD, quadratic energy)
```

Generated files go to `outputs/` and BSM checkpoints to `checkpoints/`; both are ignored by git.

## Installation

The code needs Python 3.10+ and a CUDA GPU. The experiments in the paper were run on NVIDIA A100 80GB GPUs (see Appendix G.5 of the paper for the compute used).

### Main environment

The main environment covers everything except GRPO training. It is managed with [uv](https://github.com/astral-sh/uv):

```bash
uv sync --all-extras
source .venv/bin/activate
```

### GRPO environment

GRPO training (`ita.grpo_finetuning`) needs a separate environment, because `trl` 0.24 does not work with transformers 5, which the main environment uses:

```bash
python -m venv .venv-grpo
source .venv-grpo/bin/activate
pip install -r requirements-grpo.txt
pip install -e . --no-deps
```

Model weights are downloaded from the Hugging Face Hub on first use. Set `HF_HOME` to a disk with enough space (Qwen3-8B alone needs about 16 GB).

## Data

All data is in `Data/`. Claim files are CSVs with a `claim` column and a label column (`valid` or `label`). Argument files are JSON lists of `{claim, support, attack, label}` records, where `support` and `attack` are lists of arguments.

| File | Size | Contents |
|---|---|---|
| `Training/training_true_false_uncertain.csv` | 1,000 claims | **TFU Training Claims**: True/False claims from TruthfulClaim, Uncertain claims from Rational Probabilistic Beliefs |
| `Training/training_true_false_uncertain_with_arguments_qwen.json` | 1,000 claims | TFU Training Claims with arguments generated by Qwen3-8B |
| `Training/training_true_false_uncertain_with_arguments.json` | 499 claims | Subset of TFU Training Claims with arguments generated by GPT-5 |
| `Training/training_true_false_uncertain_with_arguments_gemma.json` | 1,000 claims | TFU Training Claims with arguments generated by Gemma 4 E4B |
| `Training/Ranking/gen_gpt-5_ver_sonnet-4-5_arguments.jsonl` | 493 entries | Ranking data: four candidate arguments in descending order of quality, generated by GPT-5 and verified by Claude Sonnet 4.5 |
| `Training/Consistency/expanded_synonym_arguments_training_tfu.jsonl` | 2,330 entries | Consistency data: three GPT-5 paraphrases of each argument |
| `Validation/validation_true_false_uncertain.csv` | 150 claims | Synthetic validation claims (GPT-5, Claude Sonnet 4.5) |
| `Validation/validation_true_false_uncertain_with_arguments_{qwen,gemma}.json`, `..._with_arguments.json` | 150 claims | Validation claims with arguments generated by Qwen3-8B, Gemma 4 E4B and GPT-5 |
| `Validation/Consistency/expanded_synonym_arguments_validation_tfu.jsonl` | 1,504 entries | Consistency data for validation |
| `Evaluation/evaluation_true_false_uncertain.csv` | 750 claims | **TFU Evaluation Claims**: True/False claims from StrategyClaim, Uncertain claims from DEBATunE |
| `Evaluation/evaluation_averitec.csv` | 1,746 claims | **AVeriTeC** evaluation claims (334 True, 1,190 False, 222 Uncertain) |
| `Evaluation/evaluation_{true_false_uncertain,averitec}_with_arguments_{qwen,gemma}.json` | 750 / 1,746 claims | Evaluation claims with arguments generated by the untuned Qwen3-8B and Gemma 4 E4B |
| `Evaluation/Ranking/true_false_uncertain_gen_gpt-5_ver_sonnet-4-5.jsonl` | 149 entries | Ranking data for the BSM diagnostics (Table 2) |
| `Evaluation/Consistency/expanded_synonym_arguments_evaluation_tfu_150.jsonl` | 808 entries | Consistency data for the BSM diagnostics (Table 2) |

The evaluation claims are kept separate from all training resources. The data is derived from third-party datasets that remain subject to their own licences and terms (see [License](#license)).

## Base score model checkpoints

The BSMs are LLMs with a regression head that maps a (claim, argument, support/attack) triple to a base score in [0, 1]. In the paper's terminology, *BSM-Q* and *BSM-G* are trained on arguments generated by Qwen3-8B and GPT-5 respectively. All BSMs are primed first (`primed`): the regression head is fitted on top of the frozen backbone. The `*-primed` BSMs stop there. The others are then trained with the semantic loss (`sem`), in some cases together with the ranking (`rank`) and consistency (`con`) losses, and include a LoRA adapter for the backbone.

| Name | Paper label | Backbone | Training arguments | Losses |
|---|---|---|---|---|
| [`bsm-q-primed`](https://huggingface.co/CLArg-group/ita-bsm-q-primed) | BSM-Q (primed) | Qwen3-8B | Qwen3-8B | priming only |
| [`bsm-q-sem`](https://huggingface.co/CLArg-group/ita-bsm-q-sem) | BSM-Q (primed & sem) | Qwen3-8B | Qwen3-8B | sem |
| [`bsm-q-sem-rank-con`](https://huggingface.co/CLArg-group/ita-bsm-q-sem-rank-con) | BSM-Q (primed & sem & rank & con) | Qwen3-8B | Qwen3-8B | sem, rank, con |
| [`bsm-g-primed`](https://huggingface.co/CLArg-group/ita-bsm-g-primed) | BSM-G (primed) | Qwen3-8B | GPT-5 | priming only |
| [`bsm-g-sem`](https://huggingface.co/CLArg-group/ita-bsm-g-sem) | BSM-G (primed & sem) | Qwen3-8B | GPT-5 | sem |
| [`bsm-g-sem-rank-con`](https://huggingface.co/CLArg-group/ita-bsm-g-sem-rank-con) | BSM-G (primed & sem & rank & con) | Qwen3-8B | GPT-5 | sem, rank, con |
| [`gemma4-bsm-g-sem`](https://huggingface.co/CLArg-group/ita-gemma4-bsm-g-sem) | BSM-GPT (primed & sem), Gemma backbone | Gemma 4 E4B | GPT-5 | sem |
| [`gemma4-bsm-g-sem-rank-con`](https://huggingface.co/CLArg-group/ita-gemma4-bsm-g-sem-rank-con) | BSM-GPT (primed & sem & rank & con), Gemma backbone | Gemma 4 E4B | GPT-5 | sem, rank, con |
| [`gemma4-bsm-gemma-sem`](https://huggingface.co/CLArg-group/ita-gemma4-bsm-gemma-sem) | BSM-Gemma (primed & sem), Gemma backbone | Gemma 4 E4B | Gemma 4 E4B | sem |
| [`gemma4-bsm-gemma-sem-rank-con`](https://huggingface.co/CLArg-group/ita-gemma4-bsm-gemma-sem-rank-con) | BSM-Gemma (primed & sem & rank & con), Gemma backbone | Gemma 4 E4B | Gemma 4 E4B | sem, rank, con |

Download them into `checkpoints/`, where the configs and commands below expect them:

```bash
for name in bsm-q-primed bsm-q-sem bsm-q-sem-rank-con \
            bsm-g-primed bsm-g-sem bsm-g-sem-rank-con \
            gemma4-bsm-g-sem gemma4-bsm-g-sem-rank-con \
            gemma4-bsm-gemma-sem gemma4-bsm-gemma-sem-rank-con; do
    hf download CLArg-group/ita-$name --local-dir checkpoints/$name
done
```

To score your own arguments with a BSM, pass a CSV with `claim,is_support,argument` columns:

```bash
python -m ita.base_score_model.infer_on_arguments \
    --checkpoint-dir checkpoints/bsm-g-sem --input-csv arguments.csv --output-csv scores.csv
```

A BSM you train yourself is saved as `<output-dir>/final_checkpoint`, which has the same layout.

## Reproducing the experiments

All commands are run from the repository root. Unless stated otherwise, they use the main environment, DF-QuAD semantics and verdict thresholds of 1/3 and 2/3.

### Training base score models

Training a BSM has two stages. Priming fits the regression head to target scores obtained by prompting the backbone, and training then fine-tunes the head and a LoRA adapter through the argumentative loss.

```bash
# 1. Priming (here: Qwen3-8B backbone, GPT-5 arguments)
python -m ita.base_score_model.prime_regression_head \
    --data-path Data/Training/training_true_false_uncertain_with_arguments.json \
    --epochs 1 --lr 1e-4 \
    --output-dir outputs/bsm/priming_gpt_args \
    --target-cache outputs/bsm/priming_cache_gpt_args.json \
    --eval-data-paths Data/Validation/validation_true_false_uncertain_with_arguments_qwen.json \
        Data/Evaluation/evaluation_true_false_uncertain_with_arguments_qwen.json \
        Data/Evaluation/evaluation_averitec_with_arguments_qwen.json

# 2. Training (here: bsm-g-sem-rank-con; leave out the ranking and consistency
#    data paths to train with the semantic loss only, as for bsm-g-sem)
python -m ita.base_score_model.train_regression_head \
    --arg-data-path Data/Training/training_true_false_uncertain_with_arguments.json \
    --val-data-paths Data/Validation/validation_true_false_uncertain_with_arguments_qwen.json \
        Data/Validation/validation_true_false_uncertain_with_arguments.json \
    --test-data-paths Data/Evaluation/evaluation_true_false_uncertain_with_arguments_qwen.json \
        Data/Evaluation/evaluation_averitec_with_arguments_qwen.json \
    --checkpoint-dir outputs/bsm/priming_gpt_args \
    --output-dir outputs/bsm/bsm-g-sem-rank-con \
    --semantics dfq --lora --epochs 1 --use-arg-loss \
    --ranking-data-path Data/Training/Ranking/gen_gpt-5_ver_sonnet-4-5_arguments.jsonl \
    --consistency-data-path Data/Training/Consistency/expanded_synonym_arguments_training_tfu.jsonl
```

The other BSMs differ only in the arguments used for priming and training (`--data-path` / `--arg-data-path`), the backbone, and the evaluation files:

| BSM | Arguments | Backbone options | Validation and evaluation files |
|---|---|---|---|
| `bsm-q-*` | `..._with_arguments_qwen.json` | (default) | `*_qwen.json` |
| `bsm-g-*` | `..._with_arguments.json` | (default) | `*_qwen.json` |
| `gemma4-bsm-g-*` | `..._with_arguments.json` | `--model-name google/gemma-4-E4B-it` for priming; `--lora-target-modules q_proj.linear k_proj.linear v_proj.linear o_proj.linear gate_proj.linear up_proj.linear down_proj.linear` for training | `*_gemma.json` |
| `gemma4-bsm-gemma-*` | `..._with_arguments_gemma.json` | as above | `*_gemma.json` |

For training, `--val-data-paths` always takes the validation file matching the backbone, plus the GPT-5 one (`validation_true_false_uncertain_with_arguments.json`).

### Evaluating base score models (Tables 1 and 2)

The BSM results in Table 1 are obtained on the fixed arguments generated by the untuned Qwen3-8B. Passing the ranking and consistency data as well gives the diagnostics in Table 2:

```bash
python -m ita.base_score_model.validate_regression_head \
    --checkpoint-dir checkpoints/bsm-g-sem \
    --val-data-paths Data/Evaluation/evaluation_true_false_uncertain_with_arguments_qwen.json \
        Data/Evaluation/evaluation_averitec_with_arguments_qwen.json \
    --ranking-data-paths Data/Evaluation/Ranking/true_false_uncertain_gen_gpt-5_ver_sonnet-4-5.jsonl \
    --consistency-data-paths Data/Evaluation/Consistency/expanded_synonym_arguments_evaluation_tfu_150.jsonl \
    --semantics dfq \
    --csv-output-path outputs/bsm_eval/bsm-g-sem
```

`--csv-output-path` writes per-claim predictions (`<dataset>_predictions.csv`) for the confidence intervals below.

The same command also covers the other BSM results in the paper:
- **Primed-only BSMs (Table 4):** pass the priming checkpoint, e.g. `--checkpoint-dir outputs/bsm/priming_gpt_args`.
- **Prompted base scores in Table 2:** use `--scoring-strategy llm --model-name Qwen/Qwen3-8B` instead of `--checkpoint-dir`.
- **Optimised symmetric thresholds (Table 5):** add `--arg-data-path` with the BSM's training arguments and `--optimize-delta`. The thresholds are then chosen by balanced accuracy on the training data.
- **Quadratic energy semantics (Table 6):** train and evaluate with `--semantics qe`.
- **Gemma 4 E4B backbone (Table 7):** use the `*_gemma.json` evaluation files.

### Training argument generators with GRPO

Each GRPO run is defined by a config in `configs/grpo/`. Run them in the GRPO environment:

```bash
bash scripts/run_grpo_tuning/finetune_grpo.sh --config configs/grpo/qwen3-8b_bsm-g-sem.yaml
```

The model and logs are written to `outputs/grpo/<config name>/`, and an interrupted run resumes from its latest checkpoint. Configs that use a BSM expect it in `checkpoints/` (see above). Add `--push-to-hub` to also upload checkpoints and artefacts to your Hugging Face account.

| Config | Argument generator | Base scores during training | Reward thresholds |
|---|---|---|---|
| `qwen3-8b_llm-bs` | Qwen3-8B | prompted Qwen3-8B | 1/3, 2/3 |
| `qwen3-8b_bsm-q-sem-rank-con` | Qwen3-8B | `bsm-q-sem-rank-con` | 1/3, 2/3 |
| `qwen3-8b_bsm-g-sem` | Qwen3-8B | `bsm-g-sem` | 1/3, 2/3 |
| `qwen3-8b_bsm-q-sem-rank-con_th-0.4-0.6` | Qwen3-8B | `bsm-q-sem-rank-con` | 0.4, 0.6 |
| `qwen3-8b_bsm-g-sem_th-0.4-0.6` | Qwen3-8B | `bsm-g-sem` | 0.4, 0.6 |
| `qwen3-8b_bsm-q-sem-rank-con_th-opt` | Qwen3-8B | `bsm-q-sem-rank-con` | optimised during training |
| `qwen3-8b_bsm-g-sem_th-opt` | Qwen3-8B | `bsm-g-sem` | optimised during training |

The first three configs correspond to the *Argument Generator Model* and *Combination of Models* rows of Table 1. For the latter, the trained generator is evaluated with the same BSM it was trained with.

### Evaluating argument generators

`evaluate_grpo_run.sh` generates arguments for the TFU and AVeriTeC evaluation claims with a trained generator, then evaluates them with the base scores, semantics and thresholds from the generator's config:

```bash
bash scripts/run_evaluation/evaluate_grpo_run.sh configs/grpo/qwen3-8b_bsm-g-sem.yaml
```

By default it evaluates the final model in `outputs/grpo/<config name>/`. Use `--model` to evaluate a different checkpoint or a model on the Hugging Face Hub. For runs with optimised thresholds, it evaluates with the final thresholds from training. Results are written to `outputs/eval/<config name>/`. Run `--help` for all options.

### Baselines

The **direct baselines** predict the label without arguments. They use the TFU and AVeriTeC evaluation claims by default:

```bash
python -m ita.baselines.direct.qwen3_base_prediction    # untuned Qwen3-8B
python -m ita.baselines.direct.qwen3_sft_prediction     # supervised fine-tuning on TFU Training Claims
python -m ita.baselines.direct.qwen3_grpo_prediction    # GRPO with a reward on the predicted label (GRPO environment)
```

The **argumentative baselines** evaluate the arguments generated by the untuned Qwen3-8B with base scores from prompting Qwen3-8B, and with constant base scores of 0.5:

```bash
python -m ita.baselines.argumentative.llm_based_base_score --semantics dfq
```

Outputs are written to `outputs/baselines/`.

### Confidence intervals

`analyse_bootstrap.py` computes BCa bootstrap confidence intervals (Table 4) from prediction CSVs, such as those written by `validate_regression_head --csv-output-path`:

```bash
python scripts/analyse_bootstrap.py outputs/bsm_eval/bsm-g-sem/*_predictions.csv
```

### Additional experiments

The remaining GRPO configs vary the reward thresholds (Table 5). `_th-0.4-0.6` uses fixed thresholds of 0.4 and 0.6. `_th-opt` re-optimises the thresholds for balanced accuracy every 25 steps, starting from 0.33 and 0.66.

The Gemma 4 E4B BSMs (`gemma4-bsm-*`) are trained in the same way as the others. They are evaluated on arguments generated by the untuned Gemma 4 E4B (the `*_gemma.json` evaluation files).
